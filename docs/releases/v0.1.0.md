# v0.1.0 Release Notes

**Status:** `READY WITH LIMITATIONS` — release preparation and final validation
are complete. Tagging, pushing, publishing and deployment are pending explicit
authorization; nothing has been tagged, pushed, published or deployed.

BrainDrop v0.1.0 is the first release of the self-hostable personal inbox, task
and reminder manager. The version is set in `Cargo.toml` and
`frontend/package.json`. This is a feature release with security hardening.
The accepted limitations are documented below and in `docs/PROGRESS.md`.

## What is included

- **Core, with no external credentials:** quick capture, inbox, tasks, notes,
  ideas, reminders, categories, tags, priority, due dates, search, filtering,
  sorting, pagination, dashboard statistics and per-user settings. Manual
  capture works with no AI, Telegram or Discord configuration.
- **Authentication:** Loco's generated JWT auth with configurable registration
  and email verification, the `admin:create` task, owner-scoped data, and
  rate limits on authentication endpoints.
- **Optional AI capture:** OpenRouter parsing with reviewable suggestions,
  timezone-aware relative dates, encrypted per-user keys and graceful fallback
  to manual capture.
- **Optional notifications:** Telegram and Discord with durable delivery
  records, deduplication, retries, recovery, reminders, daily digests, overdue
  summaries and a test endpoint. Delivery is at-least-once.
- **Deployment:** one binary and one `config/production.yaml`, served SPA from
  `frontend/dist`, Docker Compose, six native release targets, an SSH release
  flow, and online SQLite backup/restore.
- **Release hardening (Task 007):** strict security headers, no-store cache
  policy for private responses, authentication rate limits with trusted proxy
  configuration, a 1 MiB body limit, input validation and account-enumeration
  safeguards, disabled OpenRouter redirects, redacted notification errors, and
  staged, permission-hardened SSH uploads.
- **Documentation:** this release note, [CHANGELOG.md](../../CHANGELOG.md),
  [SECURITY.md](../../SECURITY.md), [CONTRIBUTING.md](../../CONTRIBUTING.md),
  [CODE_OF_CONDUCT.md](../../CODE_OF_CONDUCT.md),
  [README.md](../../README.md) and [DEPLOYMENT.md](../DEPLOYMENT.md).

Detailed changes are in [CHANGELOG.md](../../CHANGELOG.md). The implementation
history is in [PROGRESS.md](../PROGRESS.md).

## Upgrade notes

- This is the first release; there is no earlier supported version to upgrade
  from.
- Production requires `DATABASE_URL`, `QUEUE_URL`, `JWT_SECRET` (base64) and
  `HOST`. Start from [`.env.example`](../../.env.example), which contains
  placeholders only.
- `REMOTE_IP_SOURCE` is new. Leave it at `ConnectInfo` unless the app sits
  behind exactly one trusted reverse proxy that overwrites `X-Forwarded-For`;
  in that case set `RightmostXForwardedFor`. Never trust a client-supplied
  forwarding header.
- BrainDrop does not send HSTS. Configure `Strict-Transport-Security` and TLS at
  the reverse proxy before public exposure.
- `AI_ENCRYPTION_KEY` and `NOTIFICATION_ENCRYPTION_KEY` are long-lived. Do not
  regenerate them during an update; rotating them makes stored credentials
  unreadable.

## Known limitations

- SQLite is single-writer: run one application replica.
- Authentication and notification test rate-limit counters are in memory and
  reset on restart; add edge limits for Internet-facing installs.
- The SPA stores its JWT in `localStorage`. The strict CSP and no-store headers
  reduce but do not eliminate the residual XSS/token-theft risk.
- Notification delivery is at-least-once; an ambiguous provider failure can
  produce a duplicate message.
- No SSH deployment, real service boot or TierHive platform behaviour was
  executed in CI. Those paths are implemented and documented, not claimed as
  verified on a target.
- Rate-limit and AI caches are in-process; a shared cache is out of scope.
- Most checked-in `dist/` archives were built before Task 007 hardening and are
  verification artifacts only (the macOS ARM64 one was rebuilt from current
  source). The manual release workflow rebuilds all six from the tagged commit
  before publication. Only the macOS ARM64 package, `linux/arm64` Docker image
  and musl ARM64 package were booted here; the other targets were cross-compiled
  but not runtime-tested.

## Validation

The single validation command is:

```sh
./scripts/ci.sh
```

It covers Rust formatting, Clippy, tests and migrations (100 unit and 98
integration tests); frontend type-check, lint, build and 36 unit tests; the
production image and its health/worker/scheduler banner; a
create-item/restart/persistence probe; an in-container backup; backup/restore
and package/deploy script checks; and 14 Playwright tests covering smoke, AI,
items, notifications, PWA and browser security. The screenshot-capture spec is
skipped unless `CAPTURE_SCREENSHOTS=1` is set. Rust request tests assert the
security headers and no-store cache policy. No real AI or notification
credentials are required.
