## Objective

Add optional AI-assisted capture through OpenRouter. A user can paste unstructured
text, receive structured item suggestions, review/edit/remove them, and save the
ones they want. Manual capture remains the default and must work with no AI
configuration.

## Scope

- Minimal OpenRouter client using `reqwest`.
- Config: API key (server and/or user), model, base URL.
- `POST /api/ai/parse` with JWT auth.
- Structured JSON output, strict validation, input/output limits, timeouts and
  per-user rate limiting.
- Prompt includes user timezone and current date; no invented deadlines.
- Treat user input as untrusted data, not instructions.
- Frontend review UI integrated with quick capture.
- Mocked provider tests; CI needs no real credentials.

- [x] Implement the OpenRouter client behind a small trait for testability.
- [x] Build the extraction prompt with delimited user input and explicit schema.

- [x] Add `POST /api/ai/parse` controller and tests with a mocked provider.
- [x] Handle provider failures with a user-safe error and a manual fallback.

## Acceptance criteria

- With AI disabled or unconfigured, capture still works manually and the UI
  explains that AI is unavailable.
- A configured provider returns validated suggestions for relative and absolute
  dates using the user's timezone.
- Items without a deadline remain without a deadline.
- Prompt-injection text in the input cannot change the extraction contract.
- Malformed or oversized provider responses are rejected safely.
- Tests pass without network access or real API keys.

## Out of scope

- Streaming responses.
- Agents, RAG, embeddings or vector databases.
- Automatic persistence of AI suggestions.
- Fine-tuning or model hosting.
- Background AI jobs (parsing is request-scoped).
